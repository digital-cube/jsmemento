memento is one monorepo with one version line: the five `@jsmemento/*` packages, the CLI and the
Docker image share one version and release together. Every release tag (the first: `v1.1.0`)
puts the packages on npm and the image on GitHub's registry, which also carries the image of
every commit of `main`; the source is [the repository](https://github.com/digital-cube/jsmemento).

<PackageTable />

- **`@jsmemento/core`** has no Node-only API (it hashes with Web Crypto), so the same package
  serves the server, the CLI, a browser and React. Its only dependency is `zod`.
- **`@jsmemento/server`** brings Fastify and its WebSocket, cookie, static and rate-limit plugins,
  Drizzle and `pg`, and `@jsudc/server` for the UDC collections. It runs on PostgreSQL or on a
  SQLite file through Node's built-in `node:sqlite`, with the migrations of both inside (SQLite
  since 1.1.0).
- **`@jsmemento/react`** keeps React as a peer (`react` and `react-dom` 18 or newer) and ships a
  stylesheet, `@jsmemento/react/styles.css`.

## The CLI in the image

`@jsmemento/cli` is the `memento` command. In the image it is `/usr/local/bin/memento`, with the
same `DATABASE_URL` and `REDIS_URL` as the server, next to `/usr/local/bin/memento-healthcheck`
(exit 0 when `GET <prefix>/api/health` answers 200; also the image's `HEALTHCHECK`):

- in the repository: `pnpm memento <command>`;
- in the Docker stack: `docker compose -f docker-compose.yaml exec memento memento <command>`.

Every command and its options: [CLI](/reference/cli/).

## The Docker image

`ghcr.io/digital-cube/jsmemento`: the server, the CLI, the examples site and the service site in
one image, multi-arch (`linux/amd64`, `linux/arm64`), with a build provenance attestation.

| tag | built from |
| --- | --- |
| `1.1.0`, `1.1`, `1`, `latest` | the release tag `v1.1.0`, the first tagged release (`latest` always follows the newest tag) |
| `main`, `edge` | the newest commit on `main` |
| `sha-<short>` | that commit |

Volumes, ports, health checks and every variable it reads: [Deployment modes](/concepts/deployment-modes/)
and [Environment variables](/reference/environment/).

## Which ones you install

| You are writing | Install |
| --- | --- |
| A memento server of your own | nothing from npm: the image, with [`docker-compose.yaml`](/get-started/docker/); or `@jsmemento/server @jsmemento/cli` on [a SQLite file](/get-started/sqlite/) |
| A Fastify app with memento inside | `@jsmemento/server @jsmemento/core fastify`, and `@jsmemento/cli` for migrations, tenants and keys |
| A React UI over memento | `@jsmemento/react @jsmemento/core react react-dom`, and `@jsudc/react` for the UDC collections |
| A script, a worker or a browser client in JavaScript or TypeScript | `@jsmemento/core` (its `MementoClient` and `MementoStream`) |
| Tools for your own vocabulary (`lookups.yaml`, translations, codegen) | `@jsmemento/lookups`, or the CLI's `memento lookups` |
| An integration in another language | nothing: one of the [client programs](/clients/), plain HTTP and a WebSocket |

The UDC side of a React UI is jsudc's: [jsudc.dev](https://jsudc.dev) lists its packages and their
peers, and [UDC collections](/concepts/udc/) says which collections memento serves.
