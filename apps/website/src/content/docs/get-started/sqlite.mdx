memento runs on PostgreSQL or on a single SQLite file. On SQLite the server needs Node 24 and a
local disk, nothing else: no Docker, no database service, no Redis. The driver is Node's
built-in `node:sqlite`, and the `memento` command line opens the same file directly.

<Aside type="caution" title="Not on npm yet">
SQLite support is in the changelog's [Unreleased](/packages/changelog/) section; the first
release with it is planned as 1.1.0, and until then no npm package and no image tag has it.
Build the packages from a clone and install the
tarballs (`pnpm install && pnpm --filter "@memento/cli..." build`, then `pnpm pack` in
`packages/core`, `lookups`, `server` and `cli`), as [Embedded in Node](/get-started/embedded/)
shows. The commands below were run that way.
</Aside>

## What SQLite gives up

Events, the Filter DSL, entity history, templates, chats, tenants and keys, the UDC collections
and the `/ws` stream answer the same as on PostgreSQL. What changes is how far it scales:

- **One server process on the file, on one host.** Your own application counts as that process
  when it [embeds the plugin](/get-started/embedded/). `memento` CLI commands next to it are
  fine. For more than one server, use PostgreSQL.
- **No Redis needed.** The process streams what it stores to its own `/ws` clients, and keeps
  the rate limits and quota counts itself. `REDIS_URL` is accepted, but it does not allow a
  second server process.
- **The examples site or the service site,** one per process, not both side by side.
- **The file on a local disk.** Never on NFS or SMB, and never opened from two hosts.

[Deployment modes](/concepts/deployment-modes/#postgresql-or-sqlite) has the features by
database, and the [SQLite guide](/reference/sqlite/) has the rest: the image and Compose on one
file, accounts and the service site, retention from cron, backups with `VACUUM INTO`, restores,
upgrades and what not to do with the file.
