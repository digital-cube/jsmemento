The memento server is a Fastify plugin before it is a process. Register it in the Fastify app you
already run and it serves the whole API under a prefix: push, lists, queries, entity history,
the `/ws` stream and the UDC collections, with its own API keys, its own error handler and its
own hooks, none of which leak into your routes. The database is your PostgreSQL, where its
tables sit next to yours, or a SQLite file next to the application.

<Steps>

1. Install the packages. They go to npm with the first release tag; until then, build and pack
   them from a clone (pnpm, through corepack, is what the repository uses):

   <Code code={install} lang="sh" title="Terminal" />

   `@memento/server` brings Fastify's WebSocket, cookie and static plugins, Drizzle and `pg`
   (SQLite is Node's built-in `node:sqlite`, nothing to install);
   `@memento/cli` is the `memento` command; `@memento/core` is the protocol and its clients.

2. The server, next to whatever your app already serves:

   <Code code={serverTs} lang="ts" title="server.ts" />

   - `DATABASE_URL` picks the database: `file:<path>` for one SQLite file,
     `postgresql://…` for PostgreSQL. `connect()` takes the driver from the URL; the rest of
     the code is the same for both.
   - `runMigrations` applies memento's migrations for that database, which ship inside
     `@memento/server`. Run it on every start: what is applied already is skipped, and on
     SQLite the first start creates the file. Every table is `memento_*`.
   - `LocalBus` is both the `publisher` (where stored events go) and the stream's `feed` (where
     `/ws` takes them from), in memory. With several processes on PostgreSQL, give each a
     `RedisPublisher` and a `RedisFeed` on the same `REDIS_URL`: an event stored by one reaches
     the `/ws` clients of all of them.
   - The `onClose` hook closes the bus and the database, so `Ctrl-C` stops it cleanly.
   - More options: `lookups` (the vocabulary of `lookups.yaml`), `defaultLocale`, `udc` (your
     own UDC collections next to memento's, or `false`), `menu`, `demoApiKey` and `accounts`
     (the self-service routes). Their meaning is in the `MementoPluginOptions` type.

3. Something to follow the stream with. `MementoStream` from `@memento/core` is the client
   `@memento/react` and `memento tail` use: it sends the key as a WebSocket subprotocol, waits
   for the welcome, and reconnects with backoff:

   <Code code={tailTs} lang="ts" title="tail.ts" />

4. Run them, with a tenant and a key made by the CLI straight in the database:

   <Code code={run} lang="sh" title="Terminal" />
   <Code code={tailOutput} lang="txt" title="What tail.ts prints" />

   Node 24 runs the `.ts` files as they are, stripping the types. `npx memento` reads the same
   `DATABASE_URL`; `create-key` prints the `mk_…` secret once, like the Docker page's.

5. Your routes and memento's, side by side, and the database file. This run used SQLite:

   <Code code={check} lang="sh" title="Terminal" />
   <Code code={checkOut} lang="txt" title="What it printed" />

   `app.db-wal` and `app.db-shm` belong to the database while it is open; after `Ctrl-C`, only
   `app.db` remains.

</Steps>

## On SQLite

Your application **is** the one server process the file allows: do not also run
`dist/server.js` on it. `memento` CLI commands next to it are fine. No Redis is needed: the
`LocalBus` streams what this process stores. A process speaks one database: `connect()` refuses
a PostgreSQL URL while a SQLite handle is open in it, and the other way round. The rest, with a
complete application that creates its own tenant and key on the first start, is in the
[SQLite guide](/reference/sqlite/#embedded-the-plugin-in-your-application).

## What you get under `/memento`

Your own route keeps answering at `/`; memento's are under the prefix, each with the scope its
key needs. The list is the [API section](/#the-api) of the home page; every parameter is in
[docs/API.md](https://github.com/digital-cube/jsmemento/blob/main/docs/API.md), the stream's
messages and close codes in
[docs/STREAMING.md](https://github.com/digital-cube/jsmemento/blob/main/docs/STREAMING.md).
