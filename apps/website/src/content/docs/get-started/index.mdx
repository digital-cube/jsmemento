memento is a server your applications push events to and read them back from. There are three
ways to have one: run it yourself (in Docker, or on one SQLite file), use the hosted service with
a key of your own, or put it inside a Node application you already have. Each page ends with a
`USER_LOGIN` pushed and read back as `User igor logged in.` and `Korisnik igor se prijavio.`

The database is PostgreSQL or a single SQLite file, with the same routes and answers on both;
[Deployment modes](/concepts/deployment-modes/#postgresql-or-sqlite) says which fits.

## What you need

- **Docker** with Compose, for the first page. The stack brings its own PostgreSQL and Redis.
- **Node 24** for the SQLite server, the embedded server and the JavaScript client (the client
  runs on Node 22 too); the other seven clients need their own toolchain, nothing else.
- **A database** when you run memento outside Docker: a SQLite file, which needs nothing but
  Node and a local disk, or PostgreSQL 18. Every table memento creates is named `memento_*`, so
  it can share your application's database.
- **Redis**, optional on both databases. One process streams its own events in memory; with
  more than one process (PostgreSQL only), Redis carries every stored event to every process's
  `/ws` clients.

Every command on these pages was run as it is written here, against a fresh clone and the stage
service; what a step prints is what it printed then, with ids shortened where they would only
be noise.
